# 무선 동글 v0.3.0 회귀 기록

`v0.2.0` 이후 무선 동글에 Runtime Combo를 추가하면서 발견한 문제와 재현 방법을 기록한다. 수정은 `2dc5af2`에 포함됐다. DYA Studio 설정 절차는 [동글 빌드와 설치](../DONGLE_BUILD.md#dya-studio)를 참고한다.

## 콤보 저장과 삭제

설정 로드 시 저장된 동작 ID를 이름으로 확인하려 했는데, 그 시점에는 ZMK의 동작 ID 테이블 로드가 끝나지 않았을 수 있었다. 이 경우 저장에 성공한 콤보도 다음 부팅에서 읽히지 않았다. 삭제할 때는 사용자 추가 슬롯을 비우는 동작과 기본 콤보를 비활성화하는 동작이 섞여, 삭제한 항목이 `Save` 뒤 다시 나타났다.

[설정과 콤보 어댑터](../zephyr/prepare_dongle_combo.py)는 로드 시 데이터 형식과 값 범위를 검사하고 동작 ID 확인은 테이블을 사용할 수 있는 시점으로 미룬다. 사용자 추가 슬롯을 삭제할 때는 설정 값, 이름, 캐시를 함께 정리하며, 기본 콤보의 삭제는 비활성 상태로 표현한다.

**회귀 확인.** DYA Studio에서 콤보를 추가하고 `Save`를 누른 뒤 동글 전원을 다시 연결한다. 다시 접속해 이름·키 조합·동작을 확인한다. 그 콤보만 삭제하고 `Save`를 누른 뒤 같은 절차를 반복해 시험 항목이 사라지고 기존 콤보가 남는지 확인한다. 저장 직후 화면과 재부팅 뒤 동글에서 다시 읽은 결과를 모두 확인한다.

## 입력 중 콤보 편집

콤보가 이미 실행된 상태에서 슬롯을 삭제하면, 해제 시점에 슬롯을 다시 조회해 기존 동작을 잃어버릴 수 있었다. 짧은 콤보가 더 긴 조합을 기다리는 동안에는 슬롯 번호만 보관해, 같은 슬롯에 새 키 조합과 동작을 저장하면 이미 누른 키로 새 동작이 실행됐다.

이미 실행한 콤보는 누름 당시의 동작과 해제 조건을 보관해 정확히 한 번 해제한다. 아직 실행하지 않은 콤보는 매칭한 설정을 보관하고, 실행할 때 슬롯의 현재 값과 비교한다. 설정이 달라졌으면 대기 중인 콤보를 취소하고 보류한 물리 키 이벤트를 일반 입력으로 돌려보낸다. [콤보 어댑터](../zephyr/prepare_dongle_combo.py)

**회귀 확인.** 콤보가 실행된 뒤 키를 누르고 있는 동안 DYA Studio에서 해당 슬롯을 삭제한다. 그 뒤 키를 떼어 기존 동작의 해제와 일반 입력을 확인한다. 대기 경로는 짧은 `Q`+`W`와 더 긴 `Q`+`W`+`E`를 겹치게 설정하고, 짧은 콤보가 대기하는 순간 같은 저장 함수로 슬롯을 편집해 비교한다. 수정 전에는 새 동작 `Z`가 실행됐고, 수정 후에는 `Q`와 `W`가 일반 입력으로 돌아왔다.

## OLED 소등 후 콤보 입력

고정 ZMK는 이벤트 리스너를 링크 순서로 호출한다. 콤보 리스너가 물리 키 이벤트를 먼저 소비하면서 `activity`가 입력을 관찰하지 못했다. 콤보의 키 동작은 실행됐지만 OLED는 꺼진 상태로 남았다. 빌드에서는 `activity`가 콤보 리스너보다 앞에 오도록 배치한다. [CMake 소스 순서](../zephyr/CMakeLists.txt)

**회귀 확인.** OLED가 Idle로 소등된 뒤 일반 키를 먼저 누르지 않고 `R`+`T` 시험 콤보만 누른다. 화면이 켜지고 콤보가 실행되는지 확인한다. CMake 구성을 바꿨다면 링크 맵에서 `zmk_position_state_changed`의 실제 구독 순서도 확인한다.

## BLE ATT 요청과 키 구독 복구

양쪽 Peripheral을 켜 둔 채 동글만 재부팅한 계측에서 ATT 요청 슬롯 5개가 모두 사용 중일 때 GATT 특성 탐색의 다음 요청이 `-ENOMEM`으로 실패했다. ATT 요청 슬롯을 10개로 늘린 비교 부팅에서는 최대 6개를 사용했고 양쪽 키 알림 구독이 성공했다. 이 수치는 해당 부팅에서 관찰한 사용량이다. [무선 동글 설정](../config/sofle_dongle_wireless.conf)

키 알림의 구독 요청 제출, 비동기 CCC 쓰기 결과, 재탐색 요청 제출은 각각 실패할 수 있다. 일반 입력과 같은 시스템 작업 큐에서 재탐색이 자원을 기다리면 정상 연결된 반쪽의 입력도 지연될 수 있으므로 전용 큐를 사용한다. 재시도 횟수는 연결별로 관리한다. 첫 재탐색 요청 자체가 `-ENOMEM`이면 150ms 뒤 남은 시도를 사용하고, 연결이 종료되거나 한도를 소진하면 재시도를 끝낸다. [BLE Central 어댑터](../zephyr/prepare_dongle_central.py)

**회귀 확인.** 양쪽을 켜 둔 상태에서 동글만 재부팅한다. `split_connected` 뒤 양쪽 슬롯에 `key_ccc_result`의 성공 코드 `0`이 기록되는지 보고 실제 문자를 입력한다. 슬롯의 물리적 좌우는 `split_side`와 대조한다. 진단 빌드에서는 오른쪽 구독 요청 실패, 비동기 CCC 오류, 첫 재탐색 요청 실패를 재현한다. 복구 대기 중 왼쪽이 입력되고, 복구 뒤 오른쪽이 입력되는지 각각 확인한다. `split_connected`만으로는 키 입력을 확인할 수 없다. [직렬 로그 읽기](../DONGLE_BUILD.md#무선-동글-phase-1)

## 생성 코드 변경과 검증 범위

- 빌드 출력 디렉터리의 생성 C 파일에 변경을 남기면 다음 빌드에서 사라진다. 제품 변경은 저장소의 Python 어댑터와 CMake에 반영한다. 의존성을 올릴 때는 고정 리비전, 콤보 어댑터의 입력 해시, 치환 전후 코드를 검토한 뒤 생성된 C 소스와 링크 맵을 확인한다.
- 실제로 발생한 실패와 시험용 오류 주입 결과를 구분한다. 진단 빌드는 재현에 사용하고 일반 빌드에서 오류 주입을 제거한 뒤 재부팅·저장·삭제·양쪽 입력을 확인한다. 릴리즈 기록에는 실기에 설치한 UF2와 CI 배포 UF2의 SHA-256을 각각 남긴다.

`v0.3.0`의 실기 검증에는 Windows 동글 후보와 진단 빌드를 사용했다. 같은 소스의 CI UF2는 빌드와 배포 파일의 체크섬을 검증했다. CI UF2에는 별도 실기 플래시 시험을 수행하지 않았다. [릴리즈](https://github.com/kalstein00/zmk-sofle/releases/tag/v0.3.0) · [CI 빌드](https://github.com/kalstein00/zmk-sofle/actions/runs/44927700418)
