# Sofle split input simulation

This runs the pinned ZMK BabbleSim BLE test harness in a disposable Linux workspace. Set `ZMK_APP` to its `zmk/app`, `BSIM_OUT_PATH` and `BSIM_COMPONENTS_PATH` to the built BabbleSim paths, and `ZMK_TEST_MODULES` to the semicolon-separated paths of the pinned runtime-sensor-rotate, runtime-input-processor and BLE-management modules. Make `west`, its Python dependencies, the host compiler and Ninja available, then run `bash tests/sofle-input/run.sh`. The script creates temporary files under that workspace's ZMK app and removes the fixture on exit; it leaves build output in the workspace.

The two simulated peripherals press the real Sofle Q and Y positions with overlapping timing. The fixture includes this repository's logical transform, dongle keymap and Central configuration; it checks the host HID states Q, Q+Y, Y and released, normalizing the order of the key slots. The POSIX-only settings options work around the pinned fork's settings initialization requirements. The simulator host uses BLE so it can observe HID reports; this does not test the actual dongle's USB endpoint, host-advertising guard, encoder, RF timing, reconnect or physical devices.
